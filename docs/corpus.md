# Real-world media corpus and workflow acceptance tests

Tracks [gaps.md G6](gaps.md#g6-no-real-world-media-corpus-or-workflow-acceptance-tests). The
corpus is a list of the media people actually bring to an editor: phone clips (iPhone HDR HEVC,
Android, variable frame rate, rotation flags), mirrorless and broadcast cameras (10-bit 4:2:2
H.264 / HEVC, AVCHD, interlaced, MPEG-2), cinema and mezzanine codecs (ProRes, DNxHR, CineForm),
screen recordings (VFR, odd sizes, browser WebM), audio-only files, multi-track sound, odd
containers and damaged files. Every file is put through the same editing job and the result is
checked with ffprobe / ffmpeg as an external oracle.

## Pieces

| piece | path |
|---|---|
| manifest (machine-readable, one `[[media]]` per file) | `tests/corpus/manifest.toml` |
| generator and checker | `scripts/corpus.py` |
| acceptance harness | `crates/engine/src/corpus_tests.rs` |
| nightly job | `.github/workflows/nightly-corpus.yml` |

## Tiers

- **small**: generated by `scripts/corpus.py generate` with ffmpeg as a black box, each under
  2 MB (the generator fails the run when one grows past it). About 80 files, 36 MB in all. These
  run every night.
- **large**: the same generator, at the sizes and lengths of the film-gap corpus (1080p / 4K,
  10–60 s). Too big for CI; the files already generated by the film-gap tools
  (`tools/make_corpus.sh`, `tools/make_gap_corpus.sh`, MANIFEST.md beside them) use the same file
  names, so pointing `REDROB_FILM_CORPUS` at that directory runs them as they are.
- **real**: camera and phone originals ffmpeg cannot make (Dolby Vision, MV-HEVC, Sony XAVC S-I,
  Lumix 10-bit 4:2:2, R3D, BRAW, ARRI MXF). `obtain` says how a person records or downloads one;
  put it at `real/<name>` in the corpus directory and add its `sha256` to the manifest to pin it.
  Media is never committed (AGENTS.md: large binary fixtures stay out of the repo).

## Expectations

- `pass`: import, cut, move, effect and export must all succeed and the output must check out.
  A failure fails the nightly job.
- `error`: import or export must fail with an error the user can read (damaged files, formats we
  do not read). Success or a panic fails the job.
- `report`: run and print the outcome without failing the job. Used for known gaps (G3 10-bit
  4:2:2, G10 containers) and open issues, so a fix shows up as `XPASS` in the log and the entry
  can move to `pass`.

A panic is a failure for every expectation (AGENTS.md §0).

## The editing job

For each present file, `corpus_tests::corpus_round_trip` runs, through the engine's commands:

1. `file.import` the file;
2. `file.newSequenceFromClip` (sequence settings from the clip);
3. `timeline.razor` at the middle of the clip (at most 1 s in), on the clip and its linked
   partners;
4. `timeline.move` the second piece 10 frames later, leaving a gap;
5. `effects.apply` Gaussian Blur on the first video piece (Volume on the first audio piece of a
   sound-only file);
6. `file.exportMedia` the first seconds of the sequence (`REDROB_FILM_CORPUS_SECONDS`, default
   3) to H.264 MP4, or WAV for a sound-only file, waiting for the job.

The output is then checked with ffprobe: the duration matches the exported range within a frame,
the decoded frame count (`-count_frames`) matches the range at the sequence rate within one frame,
an audio stream is there exactly when the source had one, and `ffmpeg -v error -i out -f null -`
decodes the whole file without an error line.

## Running it

```sh
python3 scripts/corpus.py check                         # manifest valid, >= 50 entries
python3 scripts/corpus.py generate --out target/corpus  # small tier (needs ffmpeg)
REDROB_FILM_CORPUS=$PWD/target/corpus REDROB_FILM_REQUIRE_ORACLES=1 \
  cargo test -p redrob-film-engine --profile ci corpus_ -- --nocapture
```

Without `REDROB_FILM_CORPUS` the harness uses `target/corpus` when it exists and otherwise skips
with a `SKIPPED` line, so the ordinary test run is unaffected. A manifest entry whose file is
absent is skipped by name (the summary counts them). The harness prints one line per file
(`PASS`, `FAIL`, `XFAIL`, `XPASS`, `SKIP`) and a summary. `REDROB_FILM_CORPUS_ONLY=<id>,<id>`
runs a subset.
