# Releasing Redrob Film

- **Version:** `[workspace.package] version` in the root `Cargo.toml` is the single source. `cargo xtask version` prints it; `cargo xtask version set X.Y.Z[-pre]` changes it (`Cargo.toml` and `Cargo.lock`). `redrob-film --version` and `redrob-film-cli --version` print it. The packaging scripts (`packaging/env.sh`) read `REDROB_FILM_VERSION` (override), `REDROB_FILM_BUILD_SHA` (the macOS `Info.plist` records it) and `REDROB_FILM_BUILD_DATE` (AppStream release date); the workflow sets all three.
- **Cut a release:** cut `release/X.Y.Z` from `develop`, run `cargo xtask version set X.Y.Z` there, open a pull request to `main` and merge it with a merge commit. Tag the merge commit `vX.Y.Z` on `main`, push only the tag, (the shared gitflow workflow opens the back-merge pull request `main` -> `develop` on its own; merge it with a merge commit). The tag runs `.github/workflows/release.yml`, which fails if the tag is not the Cargo.toml version, and publishes the GitHub release through the shared `redrob-labs/.github` release-publish workflow (checksums, `redrob-launcher.json`, published as latest; a version with a pre-release suffix is marked pre-release).
- **Re-runs:** pushing the same tag again (delete and re-create it) is refused once the release is published: bump it and tag again.
- **Dry run:** *Actions › Release › Run workflow* (optionally with `version: X.Y.Z-rc.N`, applied with `cargo xtask version set` in each job) builds and signs every job and publishes nothing.
- **Artifacts: exactly three targets** (`redrob-film-<version>-<os>-<arch>.<ext>`). Redrob Launcher (`redrob-launcher.json`) and the in-app updater (`apps/redrob-film-app/src/update.rs`, `asset_name_for`) look for these names, so renaming one is a breaking change:

  | Target | Assets | Notes |
  |---|---|---|
  | Linux x86_64 | `redrob-film-<v>-linux-x86_64.tar.gz` (with `install.sh`), `redrob-film-<v>-linux-x86_64.deb` | built on `ubuntu-22.04`, glibc 2.35+; `packaging/linux/package.sh` |
  | macOS universal | `redrob-film-<v>-macos-universal.dmg` (+ `redrob-film-cli-<v>-macos-universal.zip`, the headless CLI) | one image for Apple silicon and Intel; Developer ID signed, notarized, stapled; `packaging/macos/package.sh --arch universal` |
  | Windows x64 | `redrob-film-<v>-windows-x64.msi`, `redrob-film-<v>-windows-x64-portable.zip` | Authenticode-signed with Azure Artifact Signing over OpenID Connect (signer CN=McKinley Rice, Inc.); `packaging/windows/package.ps1 -Arch x64` |

  Plus `redrob-film.png` (the 512 px app icon, which `redrob-launcher.json` names as `icon` so Redrob Launcher's catalog shows this release's logo), `SHA256SUMS.txt` and `redrob-launcher.json` from the shared publish workflow. Removed on 2026-10-15 and guarded against by the CI "Release asset matrix" step: Windows x86 and arm64, Linux aarch64, AppImage (+ `.zsync`), rpm, Flatpak, the web app (`apps/redrob-film-web`, `cargo xtask web`), FreeBSD.
- **Pull-request CI vs release:** `.github/workflows/ci.yml` runs `cargo fmt --check`, `clippy -D warnings` and `cargo test` on our crates (`redrob-film`, `redrob-film-ui-egui`, `redrob-film-engine`) with `--profile ci` (root `Cargo.toml`: every dependency at opt-level 0). The release `validate` job repeats none of that: tag = version, formatting, `check_brand.py`, and a `## <version>` section in `ROADMAP.md`.
- **In-app updates:** a build that is not launcher-managed (the launcher's `installed.json` does not record its executable and `REDROB_LAUNCHER` is unset) checks `releases/latest` three seconds after start, downloads this platform's installer from the table above into the OS temp directory, verifies it against `SHA256SUMS.txt` and opens it (`open` / `msiexec /i` / `xdg-open`). `REDROB_FILM_NO_UPDATE_CHECK=1` or the Updates menu's checkbox (`<config dir>/update.json`) turns the automatic check off.
- **Fonts:** every build job checks out craft-fonts at a pinned commit (the `ref:` marked `bump deliberately`) and builds with `CRAFT_FONTS_DIR` and `CRAFT_FONTS_REQUIRED=1`, so releases embed its Japanese fonts and fail rather than ship without them. Bump the pin in every job at once.
- **Secrets:** redrob-labs organization secrets, used only by the jobs in the `release` environment (macOS, Windows, publish). macOS: `APPLE_CODESIGN_CERT_P12_BASE64`, `APPLE_CODESIGN_CERT_PASSWORD` (Developer ID certificate, imported by `packaging/macos/import-cert.sh`) and `APPLE_NOTARY_API_KEY_P8_BASE64`, `APPLE_NOTARY_API_KEY_ID`, `APPLE_NOTARY_API_ISSUER_ID` (App Store Connect API key for `notarytool`). Windows: `packaging/windows/sign.ps1` reads `WINDOWS_CERTIFICATE`/`WINDOWS_CERTIFICATE_PASSWORD` (`.pfx`) or the Azure Trusted Signing `AZURE_*` secrets; none is set for this repository yet, so Windows builds are unsigned. All are optional: a missing one produces unsigned artifacts with a warning, never a failed build.
- **Windows signing:** `packaging/windows/package.ps1` only builds and packages; the workflow signs the staged executables and then the MSI with the shared `redrob-labs/.github/actions/sign-windows` action (Azure Artifact Signing over the job's OpenID Connect login, verified with `signtool verify /pa` and the signer's CN).
- **Local packaging test:** `packaging/macos/package.sh` (ad-hoc signed DMG), `packaging/linux/package.sh`.
